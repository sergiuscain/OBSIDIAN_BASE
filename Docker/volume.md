Volume – это отдельное хранилище, которое живет само по себе, не внутри контейнера. Контейнер можно удалить, а volume и данные в нем останутся. Потом поднимаешь новый контейнер, подключаешь к нему тот же volume, и все данные на месте.

Создаем volume
```
docker volume create pgdata
```
Проверь, что хранилище появилось:
```
docker volume ls
```
Поднимаем базу с volume
```
docker run -d --name mydb -v pgdata:/var/lib/postgresql/data -e POSTGRES_PASSWORD=secret postgres:17-alpine
```
Новое здесь только флаг `-v`. Он состоит из двух частей, разделенных двоеточием, и связывает их между собой.
`pgdata` - имя нашего volume, это слева от двоеточия
`/var/lib/postgresql/data` - папка внутри контейнера, куда PostgreSQL пишет данные, это справа от двоеточия

То есть все, что база пишет в папку `/var/lib/postgresql/data` внутри контейнера, на самом деле ложится в volume `pgdata`, а не в записываемый слой. Сам путь `/var/lib/postgresql/data` – это стандартное место данных именно у PostgreSQL. У других образов путь свой, его пишут в описании образа на Docker Hub. Например, у MySQL это `/var/lib/mysql`.

А если указать другой путь:
Тут прячется неочевидная ловушка. Volume сохраняет ровно ту папку, в которую ты его смонтировал. Если написать справа другой путь, например `/var/lib/postgresql/data2`, то PostgreSQL все равно продолжит писать в свой стандартный `/var/lib/postgresql/data`, а volume повиснет на пустой папке. Данные снова окажутся в записываемом слое контейнера и пропадут при пересоздании.

Коварство в том, что ошибки не будет. База поднимется, при живом контейнере данные на месте, и кажется, что все хорошо. Проблема вылезет только когда пересоздашь контейнер, и данные исчезнут. Поэтому путь справа обязан совпадать с тем, куда приложение реально пишет данные. Для PostgreSQL это `/var/lib/postgresql/data`.


Где эти данные лежат на диске:
Вопрос, который возникает почти у всех. Volume не висит в воздухе, он лежит на твоем компьютере, просто в служебной папке Docker. Точное место показывает команда:

```
docker volume inspect pgdata
```

В ответе есть строка `Mountpoint`, обычно это `/var/lib/docker/volumes/pgdata/_data`. На Windows и Mac Docker крутится внутри своей виртуальной машины, поэтому путь ведет внутрь нее, а не в проводник, и открыть его мышкой не выйдет. Так и задумано. Место выбирает Docker, лазить туда руками не нужно, с данными работают через контейнер.

Но место можно выбрать и самому. Так делают, когда системный диск маленький, а база ожидается на десятки гигабайт, или когда данные надо положить на отдельный диск. Тогда слева от двоеточия пишут не имя, а путь:

```
docker run -d --name mydb -v /mnt/big-disk/pgdata:/var/lib/postgresql/data -e POSTGRES_PASSWORD=secret postgres:17-alpine
```

Слева имя – это named volume, местом распоряжается Docker. Слева путь – это bind mount, папку выбираешь ты. Для баз обычно берут named volume, а bind mount – когда данные должны лежать в конкретном месте.


Главное из урока:
Volume хранит данные отдельно от контейнера, поэтому они переживают его удаление. Создаешь volume через `docker volume create`, подключаешь флагом `-v имя:путь`, где путь – это папка данных внутри контейнера. Теперь контейнер можно пересоздавать сколько угодно, данные останутся.
