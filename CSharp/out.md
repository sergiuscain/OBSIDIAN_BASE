`out` - Модификатор параметра метода, при котором аргумент передаётся **по ссылке** и служит для **возврата значения** из метода.

## Правила:
- В сигнатуре метода тип указывается **обязательно** (`out int x`), `var` недопустим.
- Метод **обязан** присвоить значение `out`-параметру до выхода — иначе ошибка компиляции.
- Вызывающий код **не обязан** инициализировать переменную до вызова — значение из неё в метод не передаётся.
- Внутри метода значение можно читать только после присвоения
```csharp
public static bool IsEmpty(string question, out string error)
{
    error = null;                          // обязательное присвоение
    if (string.IsNullOrEmpty(question))
    {
        error = "Вопрос не может быть пустым или null";
        return false;
    }
    return true;
}
```
### Проблема (до C# 7)
Переменную приходилось объявлять **отдельно** от места вызова, что ухудшало читаемость при большом объёме кода:
```csharp
string error;                  // объявление здесь
// ... много кода ...
IsEmpty("Hello", out error);   // использование здесь
Console.WriteLine(error);
```
### Решение (C# 7): out-переменные
Переменную можно объявить **прямо в месте вызова**:
```csharp
IsEmpty("Hello, world!", out string error);
Console.WriteLine(error);      // доступна и после вызова
```
Или с выводом типа через `var` (только при вызове, не в сигнатуре метода):
```csharp
IsEmpty("Hello, world!", out var str); //Здесь используется var и это допустимо
Console.WriteLine(str);
```
Переменная, объявленная как out при этом должна быть уникальной в области видимости, где используется метод с ней. И она может быть использована в этой же области видимости:
```csharp
static void Main()
{
    string s = "1.5";
    if (int.TryParse(s, out var i)) //Переменная i обявляется как out
    {
        Console.Write(i);
    }
    Console.Write(i); //И используется за пределами метода
    //При этом, мы не можем обявить ещё одну переменную i
    //int i; - эта строка вызовет ошибку. 
    //Переменная с таким именем уже существует в области видимостьи
}
```
### Wildcard `_` (C# 7)
У нас есть метод с out:
```csharp
public static void GetNumbers(out int x, out int y)
{
    Random rnd = new Random();
    x = rnd.Next(1, 100);
    y = rnd.Next(1, 100);
}
```
В версии **C# 7** мы можем игнорировать переменную `out` если она нам не нужна:
```csharp
static void Main()
{
    GetNumbers(out var x, out _); //Здесь мы используем out переменную `x`, 
    //но out переменную `y` игнорируем
    Console.WriteLine($"x = {x}");
}
```
### out в шаблонах Try... (TryParse)

```csharp
if (DateTime.TryParse(s, out DateTime date))  // объявление в месте вызова
    Console.WriteLine(date);
```
**Поведение при неудаче:** если парсинг не удался, в блок `if` не попадаем, но `out`-==🟠переменная уже проинициализирована значением по умолчанию== и доступна после вызова:
```csharp
string s = "";
if (DateTime.TryParse(s, out DateTime date)) 
	{ /* не выполнится */ }
Console.WriteLine(date);   // 01.01.0001 0:00:00 (default(DateTime))
```
